# 写真ビューア（photo-viewer）

同期仕様ID / 版: **PV-SPEC-2026-10-v14 / version 14.0**

PC に取り込んだ Amazon Photos 由来の写真から、スマートフォンで閲覧できる静的な写真ビューアを生成し、GitHub Pages で公開します。
操作の流れは別冊「ユーザー向けセットアップ・運用手順書」（同じ同期仕様ID・版）に従ってください。本 README は手順書と同じコマンドを使い、各コマンドの動作と仕様を補足します。

> **重要:** GitHub Pages は誰でも閲覧できる公開 Web サイトです。URL を知っていれば誰でも見られます。
> `noindex` で検索エンジンへの登録を抑止していますが、アクセス制限ではありません。人に見せたくない写真は置かないでください。

## 共通仕様（S-01～S-10）

| ID | 仕様 | 実装 |
|---|---|---|
| S-01 | 年は1月1日～12月31日 | `year` = `date`（Asia/Tokyo）の西暦年。4月始まりの年度（fiscalYear）は使わない |
| S-02 | 新しい撮影日時順・同日時は相対パス昇順 | 生成時に並べ替え、画面側は JSON の順序を保つ安定ソート |
| S-03 | 480×480 WebP サムネイル | EXIF の回転を補正してから中央を正方形に切り抜き |
| S-04 | 詳細画像は長辺最大1920px | 元の縦横比を維持。1920px 以下の写真は拡大しない。v10 から、動く一覧用の中間画像（`mids/`、元の縦横比・長辺最大800px）も作る |
| S-05 | 一覧（v5・v6・v7・v10・v12・v13・v14 で変更） | v13 から年で分けず、**全部の写真を新しい順に1つの一覧**にする。各写真に目録番号（古い順の通し番号。「No.」は付けない）と撮影日。<br>**動く一覧**（ふだん）: 最初に見せ方（パターン）を選ぶ（v12）。<br>パターン1「散らばる」: 写真を元の縦横比のまま大小ばらばらに、終わりのない平面へ散らす。散らし方は読み込むたびに変わる（v13）。スクロール・ドラッグで上下左右に動き、写真ごとに違う速さで追いかけて、止まると元の並びに戻る。「Change view」の文字も写真と一緒に散らす（v13）。<br>パターン2「並べる」（v12。v13 までの名前は「列」）: 写真を縦長（4:5）の枠で列に並べ（スマホ・幅910px未満は3列、それ以上は7列）、スクロールすると列ごとに遅れてついてくる（中央の列がいちばん早く、外側ほど遅い）。<br>パターン3「揺れる」（v14）: 傾きの違う紐を上から下へ何本も張り、写真（ふちなし・元の縦横比）をクリップで吊るして右横に札（番号・年・月日）を下げる。スクロールの勢いとときどき吹くそよ風で、写真と札が振り子のように揺れる。<br>どれも表紙の写真は出さない。<br>**動かない一覧**（端末の「視差効果を減らす」設定がオンのとき）: 先頭に表紙の写真（`coverPhoto` で選択、未指定はいちばん新しい写真）を元の縦横比で大きく表示し、一覧は正方形をスマホ縦向きで2列、幅 640px 以上で3列 |
| S-06 | 年タブ（v13 で廃止） | v7〜v12 は写真のある年だけを新しい順にタブで選んだ（v11・v12 では年の文字を写真と一緒に散らした）。v13 から年で分けず、年のタブ・「〜年の〜枚」は出さない。撮影年の範囲（例: 2025–2026）だけを小さく表示する |
| S-07 | 全画面スライド | 左右スワイプ・前後ボタン・閉じる・Escape・矢印キー |
| S-08 | 公開画像の EXIF 削除 | GPS を含む EXIF・XMP・ICC を書き込まない（色は sRGB に変換） |
| S-09 | 原本は Git 対象外 | `.gitignore` で `source_photos/` を除外。publish.ps1 でも確認 |
| S-10 | 検証成功後だけ公開 | 一時フォルダーで生成→検証→合格時だけ置換。失敗時は既存の正常版を維持 |

v8 で追加した **小話**（写真ごとの短い文章と、それを書く管理ページ）は **v9 で廃止**しました。サイトには写真・番号・撮影日だけを表示します。

追加仕様（v10）: **動く一覧** — 一覧の写真がスクロールで写真ごとに違う速さで動きます（Codrops の作例「Infinite Layers Grid」の動きの考え方を参考に、このサイト用に書いたもの。コードや写真は使っていません）。動きは端末の「視差効果を減らす」設定がオンのときは一切しません（v9 までの動かない一覧を表示）。

追加仕様（v12）: **見せ方（パターン）を選ぶ** — 開くと最初に見せ方を選ぶ画面を出します。v10・v11 の動く一覧が「パターン1（散らばる）」、Codrops の作例「Elastic Grid Scroll」の動きの考え方を参考にした「パターン2（列）」を追加しました（どちらもこのサイト用に書いたもの。作例のコードや写真は使っていません）。文字は手書き風の Klee One をやめ、ドット文字の DotGothic16 を小さめの大きさで使います。

追加仕様（v14）: **パターン3「揺れる」** — 暗室で現像した写真を干すように、斜めに張った紐に写真を吊るし、スクロールの勢いとそよ風で揺らします（このサイト用に考えた見せ方です）。パターン2の名前を「列」から「並べる」に変えました。

追加仕様（v13）: **年で分けない** — 年のタブ（上部のバー）・散らした年の文字・「〜年の〜枚」をやめ、全部の写真を新しい順に1つの一覧にして、目録番号（「No.」なし）と撮影日だけを添えます。見せ方を選び直すボタンは英語の「Change view」（選ぶ画面の見出しは「Choose a view」）にし、パターン1では写真と一緒に散らします。パターン1の散らし方は読み込むたびに変わります。

## 初回セットアップ

例として `C:\PhotoViewer\photo-viewer` に配置した場合です（手順書 3.2～3.4）。

```powershell
cd C:\PhotoViewer\photo-viewer
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item config.example.json config.json
```

- `Activate.ps1` で「このシステムではスクリプトの実行が無効になっている」と表示された場合は、その PowerShell ウィンドウだけ許可してから再実行します:
  `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`
- `pillow-heif` をインストールできない場合は requirements.txt からその行を削除してください（HEIC はスキップされ、ログに記録されます）。
- 以降のコマンドは、仮想環境を有効にした（プロンプトの先頭に `(.venv)` が出ている）状態で実行します。

### 設定ファイル（config.json）

| キー | 既定値 | 説明 |
|---|---|---|
| `sourceDir` | `source_photos` | 原本フォルダー。手順書どおり `source_photos` のままにします（絶対パスも可。出力フォルダーの中は不可） |
| `thumbSize` | `480` | **固定値（S-03）。変更しないでください**（480 以外にすると生成・検証がエラーで停止） |
| `detailMaxEdge` | `1920` | **固定値（S-04）。変更しないでください**（1920 以外にすると生成・検証がエラーで停止） |
| `allowedExtensions` | `.jpg .jpeg .png .webp .heic .heif` | 対象にする拡張子。それ以外（動画など）はスキップしてログに記録 |
| `siteTitle` | `Photographs` | サイト名（例: `"Daily"`。未設定時は「写真」）。ブラウザーのタブの名前と、読み上げの見出しに使います（v11 から画面には出しません） |
| `coverPhoto` | （空） | トップに大きく表示する写真。`source_photos` からの位置で書く（例: `"2026/2026-09-05_14-45-52_000.jpeg"`。`source_photos\\…` やフルパスでも可）。空・見つからない場合はいちばん新しい写真（見つからないときはログに警告）。公開データには写真のIDだけが入り、ファイル名は公開されません |
| `thumbQuality` / `detailQuality` | 80 / 85 | WebP の画質（1～100） |
| `shrinkGuardRatio` | 0.5 | 公開中の写真数（10枚以上）に対して、この割合未満へ減る場合は停止 |
| `jobs` | 0 | 並列変換数（0 = 自動、最大4） |

v8 で管理ページのログイン情報として書き込まれた `admin` は、v9 では使いません（残っていても動き、生成時に「消して構いません」と表示します）。

`config.json` は `.gitignore` 対象のため GitHub へは送られません（確認: `git check-ignore -v config.json` で `.gitignore` の行が表示されれば除外されています）。

## 写真を置く

原本を `source_photos\` にコピーします（サブフォルダーも再帰的に読み込みます）。原本は読み取るだけで、削除・上書き・移動はしません。

- `source_photos` が Git の対象外であることの確認: `git check-ignore -v source_photos\写真のファイル名.jpg`
- 手順書 9章のとおり、コピー完了（ファイルサイズ・更新時刻が変化しないこと）を確認してから生成します。コピー途中のファイルを読み込むと、壊れた画像としてスキップされるか、一部が欠けた画像になることがあります（コピー完了後に生成し直すと正しい画像に置き換わります）。

## 生成と検証

手順書 5章のコマンドです。

```powershell
python tools/build_gallery.py --config config.json
python tools/validate_build.py --config config.json
python -m pytest -q
```

**build_gallery.py**
- `photos\<年>\` に詳細画像、`thumbs\<年>\` に 480×480 のサムネイル、`mids\<年>\` に動く一覧用の中間画像（長辺最大800px）、`data\photos.json` を作ります。
  v9 までの公開データから初めて生成するときは、中間画像を作るため全写真を変換し直します（時間が少し長くかかります）。
- 撮影日時は次の順で決めます（`dateSource` に記録）。
  1. EXIF の DateTimeOriginal（`exif`）。タイムゾーン（OffsetTimeOriginal）があれば Asia/Tokyo に換算し、なければ Asia/Tokyo の時刻とみなします。
  2. ファイル名の日時（`filename`）。例: `2026-09-05_14-45-52_000.jpeg`（Amazon Photos）、`IMG_20260905_144552.jpg`、`Screenshot_20260905-144552.png`。
     ファイル名の最初に現れる「日付＋時刻（秒まで）」を Asia/Tokyo の時刻として使います。重複ダウンロード時の `(2026-10-12T16_03_05.577)` のような後置きは使いません。
  3. ファイルの更新日時（`mtime`）。コピーやダウンロードをした時刻になっていることが多いため、一覧では「（ファイル更新日時）」と表示します。
- 内容が同じ写真（SHA-256 が一致）は1枚にまとめます（相対パス順で先のものを採用）。
- 破損した画像・対象外の拡張子・pillow-heif 未導入時の HEIC はスキップし、件数をログに出します（`--strict` で1件でもあれば失敗）。
- 2回目以降は、変わっていない写真の変換結果を再利用します。ログは `logs\build_*.log`（直近30件）。

**validate_build.py**
JSON 構文、必須キー、year と date の一致（12月31日と1月1日が別の年になること）、並び順、ID 重複、参照先の存在、画像の実読込、サイズ、メタデータの有無、参照されていない公開画像、外部 URL 依存、設定ファイルの仕様固定値を確認します。

**pytest**
試験画像を一時フォルダーに作って生成・検証・公開処理・画面を試験します（実際の写真と出力には触れません）。

検証や試験が1つでも失敗した場合は公開へ進まないでください（publish.ps1 は自動で停止します）。


## GitHub へ公開

手順書 7章のコマンドです（初回のみ）。

```powershell
git init
git branch -M main
git add .
git status
git commit -m "Initial photo viewer"
git remote add origin https://github.com/YOUR_NAME/photo-viewer.git
git push -u origin main
```

- `git status` に `source_photos/.gitkeep`・`photos/.gitkeep`・`thumbs/.gitkeep`・`mids/.gitkeep`（中身が空のフォルダー保持用ファイル）が出るのは正常です。
  それ以外の `source_photos/` のファイル、`config.json`、`logs/`、`.build/`、`.venv/`、`.jpg` などの元写真が出ていれば commit しないでください。
- GitHub の Settings → Pages で Source を「Deploy from a branch」、ブランチを `main`・フォルダーを `/(root)` にして Save します。
- URL は `https://YOUR_NAME.github.io/photo-viewer/` です。ページ内のパスはすべて相対 URL のため、このサブパスでそのまま動きます。

## 写真追加と更新（publish.ps1）

手順書 9章のコマンドです。

```powershell
PowerShell -ExecutionPolicy Bypass -File .\tools\publish.ps1
```

次の順に実行し、どこかで失敗した場合は commit / push を行いません。

1. 排他ロック 2. 仮想環境（`.venv`）の確認 3. Git の事前確認 4. 生成 5. 検証 6. 試験（pytest） 7. Git 対象の安全確認 8. 差分がある時だけ commit / push

**テスト成功時だけ push されたことの確認:** `logs\publish_日時.log` を開き、`6/8 試験に合格しました` の後に `8/8 push しました` があることを確認します。
変更がなければ `8/8 公開内容に変更はありません` と記録され、commit / push は行いません。

**デスクトップから公開する（ダブルクリック）:** `tools\publish.bat` が上のコマンドと同じことをします。デスクトップの「公開する」は、このファイルを呼び出すだけのアイコンです。
作り直すときは、エクスプローラーで `tools\publish.bat` を右クリック →「その他のオプションを確認」→「送る」→「デスクトップ（ショートカットを作成）」で
アイコンを作り、名前を「公開する」に変えます。終わると画面の色で結果がわかり、キーを押すまで閉じません。

| 画面の色 | 意味 |
|---|---|
| 緑 | 完了（写真に変更があれば公開。サイトへの反映は1〜2分後） |
| 黄 | 安全装置で停止（終了コード 2）／別の公開が実行中（終了コード 75） |
| 赤 | 失敗。commit / push はしていません。赤い行を確認します |

| オプション | 動作 |
|---|---|
| `-DryRun` | commit / push せず、公開予定のファイルを表示 |
| `-NoPush` | commit まで（公開準備）。あとで `git push` すると公開 |
| `-Unattended` | 無人実行用。GitHub の認証入力を待たずに失敗として終了し、ログに記録 |
| `-AllowEmpty` | 原本0件のとき、公開中の写真をすべて消すことを許可 |
| `-AllowShrink` | 写真数の大幅減少を許可 |

- push に失敗した場合（通信断・認証切れなど）、commit は PC 内に残り、**次回の publish.ps1 実行時に自動で再送**します。
- publish.ps1 が commit するのは `index.html css js fonts data photos thumbs mids .nojekyll` だけです。tools・tests・README などを変更した場合は通常どおり自分で commit してください。

## 自動更新（タスク スケジューラー）

手順書 10章のとおり、手動更新が安定してから登録します。

| 項目 | 設定値 |
|---|---|
| 操作 | プログラムの開始 |
| プログラム/スクリプト | `powershell.exe` |
| 引数の追加 | `-NoProfile -ExecutionPolicy Bypass -File "C:\PhotoViewer\photo-viewer\tools\publish.ps1" -Unattended` |
| 開始（オプション） | `C:\PhotoViewer\photo-viewer` |
| 設定タブ「タスクが既に実行中の場合に適用される規則」 | 新しいインスタンスを開始しない |

- publish.ps1 自体も排他ロックを持つため、手動実行と重なった場合は後から起動した方が終了コード 75 で何もせず終了します。
- 結果はタスクの「前回の実行結果」（終了コード）と `logs\publish_*.log` で確認します。通信断・GitHub 認証切れは「push に失敗しました」、PC のスリープで中断された場合はログが途中で終わります（次回実行時に未送信分を再送）。
- 自動化後も、公開対象の写真を定期的に目視確認してください。

## 画面の動作

- 色と文字: いつも白い背景に黒い文字です（スマホをダークモードにしていても同じ）。
  文字はドット文字の DotGothic16 で、小さめ（12px 以下）にしています（v12。v11 までの手書き風 Klee One から変更）。画面の文言・英数字・かなだけを取り出した小さな版（`fonts/dotgothic16-subset.woff2`、約15KB）を最初に読み込みます。
  フォントに入っていない文字は端末の日本語書体で表示します。画面の文言に新しい漢字を足したときは `python tools/make_font_subset.py <DotGothic16-Regular.ttf>` で作り直します（試験が知らせます）。
- サイト名: 画面には出しません（v11）。ブラウザーのタブの名前と、読み上げの見出しにだけ使います。
- 年: 年では分けません（v13）。全部の写真が新しい順に1つの一覧に並びます。年のタブ・「〜年の〜枚」はなく、撮影年の範囲（例: 2025–2026）だけを小さく表示します。
  （写真の置き場所 `photos\<年>\` などと photos.json の `year` は、生成の決まり S-01 としてそのまま使います）
- 目録番号: いちばん古い写真が 01 の通し番号です。「No.」は付けず、数字だけを出します（v13）。過去の日付の写真を追加すると、それより新しい写真の番号は1つずつ増えます。
- 選んだものの印: キーボードの Tab などで選んだ写真・ボタンには、青い枠ではなく、左上と右下に黒いかぎ「 」を付けます（v11）。指やマウスで押したときは付きません。

**見せ方を選ぶ（v12。v13 から英語）**
- 開くと最初に見せ方を選ぶ画面（見出し「Choose a view」）が出ます。パターン1「散らばる」・パターン2「並べる」・パターン3「揺れる」から選びます（小さな図と説明付き）。
- 同じタブで再読込・戻る操作をしたときは選ぶ画面を出さず、選んだ見せ方のまま表示します。新しいタブや再訪問では選ぶ画面から始まり、前回選んだ見せ方が選ばれた状態（「前回」の印付き）になります。
- Escape で閉じると前回の見せ方（初めてならパターン1）で表示します。
- 「Change view」でいつでも選び直せます（パターン1では写真と一緒に散らばっている文字、パターン2では撮影年の範囲の横、パターン3ではいちばん上の紐の札）。選び直すと一覧の位置は最初に戻ります。
- 端末の「視差効果を減らす」設定がオンのときは選ぶ画面を出さず、動かない一覧を表示します。

**パターン1「散らばる」（v10。v12 からパターン1）**
- 全部の写真を、元の縦横比のまま大・中・小ばらばらに、画面より広い平面へ散らします。
  散らし方（どの写真がどこに・どの大きさで）は**読み込むたびに変わります**（v13。再読込でも変わり、最初に見える写真も変わります）。画面を回したときやパターンを選び直したときは、同じ読み込みの間なので同じ散らし方です。
  画像は中間画像（`mids/`、長辺800px）を使い、画面に近づいてから読み込みます。各写真の下に目録番号と撮影日を添えます。
- 動かし方: スマホは指で上下左右にドラッグ（離すと少し勢いで進む）、PC はホイール・トラックパッド（Shift＋ホイールで横）、マウスのドラッグ、矢印キー・PageUp/PageDown・スペース。
  動かすと写真ごとに少しずつ違う速さで追いかけ、止まると元の並びに戻ります。ページ自体はスクロールしません。2本指の拡大はできます。
- 端まで行くと反対側から同じ並びが続きます（終わりがありません）。写真が少ないときは並びを複製して画面を埋めます（複製は読み上げ・Tab の対象外）。
- 開いた直後（再読込を含む）は、画面の中央に重なった写真が、それぞれの場所へ広がっていきます（約2〜3秒）。
- 番号と撮影日は、写真が画面に入るたびに1行ずつ下から現れます。写真は画面に入ると、白くぼやけた像から色と輪郭が浮かび上がるように現れます（現像）。
- PC では、マウスの位置に合わせて写真が少しずれます（大きい写真ほど大きく動き、奥行きが出ます）。
- 写真をタップ（クリック）すると全画面表示。ドラッグしたときは開きません。Tab キーで写真を新しい順に選ぶと、選んだ写真が見える所まで一覧が動き、Enter で開きます。
- 「Change view」の文字も写真と同じように散らばり、写真と同じ動きをします（v13。v11 の年の文字の代わり）。開いた画面に1つ、ほかはだいたい1画面に1つずつ置きます。押すと見せ方を選ぶ画面が出ます。
  キーボードでは、Tab で最初に移る「Change view」ボタン（画面の右下。キーボードで移ったときだけ見える）を使います。
- 表紙の写真（`coverPhoto`）は出しません。撮影年の範囲は画面の下に小さく表示します。

**パターン2「並べる」（v12。v13 までの名前は「列」）**
- 全部の写真を縦長（4:5）の枠に収め（はみ出す部分は切り取り）、スマホと幅910px未満は3列、それ以上は7列に並べます。左上から横に読むと新しい順です。画像は中間画像（`mids/`）です。
- 各写真の下に「36 - 2026.10.20」のように目録番号と撮影日を添えます（v13 から「No.」なし）。列が細くて1行に収まらない画面（幅の狭いPCの7列など）では、すべての写真で番号と撮影日を2行に分けます（「…」で切れないように。行の高さはそろえます）。
- ページは普通にスクロールします。スクロールすると、列ごとに遅れてついてきます（中央の列がいちばん早く、外側の列ほど遅い）。止まると行がそろいます。
- 撮影年の範囲と「Change view」は一覧の上の左側に小さく並べます（スクロールすると一緒に上へ流れます）。
- 写真をタップ（クリック）すると全画面表示。Tab キーで写真を順に選び、Enter で開きます。画面の幅が変わると列の数を並べ直します。

**パターン3「揺れる」（v14）**
- 暗室で現像した写真を干すように、傾き（2〜7度）の違う紐を上から下へ何本も張ります。紐どうしは交差しません。
- 写真は元の縦横比のまま、ふちなしで、上の真ん中を小さなクリップで紐に留めます。1本の紐に吊るす枚数は、スマホで1〜2枚、タブレットで2〜4枚、PC で3〜6枚です（枚数が少ない紐の写真は大きくなります）。新しい写真から順に、上の紐の左から吊るします。画像は中間画像（`mids/`）で、画面に入ると現像の演出で浮かび上がります。
- 写真の右横に、糸で札を下げます。札には番号・年・月日の3行（例: 47 / 2026 / 10.11）を書きます。
- いちばん上の紐には、撮影年の範囲（2025 – 2026）と「Change view」の札も吊るします。「Change view」を押すと見せ方を選ぶ画面が出ます（キーボードでは、Tab で最初に移る右下の「Change view」ボタン）。
- ページは普通に縦へスクロールします。スクロールの勢いで写真と札が傾き、止まると振り子のように揺れて数秒で収まります（大きい写真ほどゆったり揺れます。いちばん大きく傾いて約20度）。
- 何もしなくても、ときどき（6〜14秒おき）左から右へそよ風が通り抜け、写真と札を少しだけ（2度ほど）揺らします。
- 並びは写真ごとに決まっていて、再読込しても同じです。同じタブで再読込・戻る操作をすると、スクロール位置も戻ります。画面の幅が変わると並べ直します。
- 写真をタップ（クリック）すると全画面表示。閉じるとその写真に戻ります。Tab キーで写真を新しい順に選び、Enter で開きます。

**動かない一覧（端末の「視差効果を減らす」設定がオンのとき）**
- 動きを一切しない、v9 までの一覧です。現像・広がる動きもしません。設定を途中で変えると、その場で切り替わります。
- 上に残るバーはありません（v13 で年のタブとともに廃止）。
- 表紙の写真: 先頭に中央寄せで大きく表示します（`coverPhoto` で選択）。タップすると、一覧の中のその写真の位置から全画面表示します（前後は一覧の写真）。
  表紙と一覧のあいだに撮影年の範囲を小さく表示します。
- 一覧: 全部の写真の正方形（スマホ縦向き2列、横向き・PC は3列）。写真ごとに目録番号と撮影日を添えます。60枚ずつ追加表示し、写真は画面に近づいてから読み込みます。

**共通**
- 全画面: 写真をタップ。白い背景に写真を表示し、写真の下に撮影日時を表示します。左上に目録番号を出します。左右スワイプ／写真の下の「‹ ›」／矢印キーで前後（年をまたいで全部の写真）、×／Escape で閉じます。端では止まります（ループしません）。
- 読込中・写真0件・JSON の読込失敗（再読み込みボタン付き）・旧形式データ・画像の読込失敗をそれぞれ表示します。表示できないデータがあるときはその件数も小さく出します。
- 想定ブラウザー: iOS 15.4 以降の Safari、最新の Android Chrome、PC の最新ブラウザー（実機での確認は手順書 8章）。

### 状態保存と再読込の仕様

| 項目 | 保存先 | 再読込・戻る操作をしたとき |
|---|---|---|
| 見せ方（パターン）（v12） | sessionStorage `pv:pattern` | 同じタブでの再読込・戻る操作では選ぶ画面を出さずに同じ見せ方。新しいタブや再訪問では選ぶ画面から |
| 前回選んだ見せ方（v12） | localStorage `pv:patternLast` | 選ぶ画面で「前回」の印を付け、最初に選ばれた状態にする。Escape で閉じたときもこの見せ方 |
| パターン1の位置 | 保存しない（v13） | 散らし方が読み込むたびに変わるので、いつも最初の位置から広がる |
| パターン2のスクロール位置（v12） | sessionStorage `pv:elastic` | 同じタブでの再読込・戻る操作で復元。新しいタブや再訪問では先頭から |
| パターン3のスクロール位置（v14） | sessionStorage `pv:sway` | 同じタブでの再読込・戻る操作で復元。新しいタブや再訪問では先頭から |
| スクロール位置（動かない一覧） | sessionStorage `pv:scroll` | 同じタブでの再読込・戻る操作で復元。新しいタブや再訪問では先頭から |
| 全画面表示中の写真 | 保存しない | 一覧（保存した位置）に戻る |

- スクロール位置は「画面上端の写真＋ずれ」で保存するため、写真が追加されても同じ写真の付近に戻ります。
- v12 までの保存値（選んだ年 `pv:selectedYear`、パターン1の位置 `pv:drift`、年ごとのスクロール位置）は使わず、見つけたら消します（v13）。
- `data/photos.json` は毎回サーバーへ更新確認して取得します。公開後に再読込すると新しい写真が表示されます（GitHub Pages の反映には数分かかることがあります）。

## 安全装置

- **排他:** 生成と公開は OS のファイルロックで1つずつしか動きません。実行中に起動すると終了コード 75 で停止します。異常終了してもロックは自動で解放されます。
- **原子的な置換:** `.build\` 内で全量を作り、検証に合格したときだけ `photos\`・`thumbs\`・`mids\`・`data\photos.json` を入れ替えます。入れ替え中の失敗は自動で元に戻し、強制終了した場合も次回起動時に復旧します。
- **0件・大幅減少:** 原本フォルダーが見つからない／空のときに公開中の写真を消さないよう停止します（終了コード 2）。意図的な場合は `--allow-empty` / `--allow-shrink`（publish.ps1 では `-AllowEmpty` / `-AllowShrink`）。
- **公開前チェック:** 原本・元形式の画像・動画・鍵ファイル・25MB 超のファイル・PC 内のパスを含む JSON が commit 対象にあれば停止します。

出力の初期化（公開データの一括削除）機能はありません。写真を減らす場合は原本を減らして再生成します。

## 旧形式（fiscalYear）からの移行

- `build_gallery.py` を実行すると、旧形式の `data/photos.json` を検出してログに記録し、原本から `year` 形式で作り直します。
- 原本がない場合は `python tools/build_gallery.py --migrate-legacy` で、各写真の `date` から1月1日始まりの `year` を求めて変換します。
  `date` がない、または旧画像が新仕様（480×480 WebP など）を満たさない場合は、ファイルを変更せずに停止します（終了コード 3）。
- 画面側は旧形式のデータを受け取ると、表示を停止して再生成を促すメッセージを出します。
- `validate_build.py` は `fiscalYear` を含むデータを不合格にします。
